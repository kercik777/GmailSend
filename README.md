# ✨ Aurora Mail

Полностью переработанный дизайн и код приложения для отправки писем с вложениями через SMTP.
Было: одно поле «Edit Text» и три серые кнопки. Стало: тёмная «аврора-стеклянная» дизайн-система,
живой фон, настройки с сохранением почты и пароля приложения, вложения из системного
пикера, статистика, черновики и экран успеха с конфетти.

> 📱 **Посмотреть дизайн без сборки:** откройте `design-preview/index.html` в браузере
> (или живой предпросмотр, если он запущен в Arena). Там три интерактивных экрана и переключатель палитр.

## Что нового

### Дизайн
- Тёмная палитра «Aurora»: фиолетовый → мятный → розовый, глубокий фон, стеклянные градиентные карточки, тонкая обводка, мягкие тени.
- Кастомный `AuroraView`: три медленно дрейфующих световых пятна и мерцающие звёзды (чистый Canvas, без библиотек).
- Новый адаптивный логотип/иконка (`adaptive-icon` + PNG для всех плотностей), фирменный градиент.
- Material-поля с иконками, состоянием фокуса и ошибками, пульсирующий индикатор статуса, ripple-эффекты.
- Экран успешной отправки: overshoot-анимация карточки, кольцо с галочкой и 56 конфетти-частиц.
- Даже само письмо приходит красивого вида: HTML-версия с градиентным заголовком + plain-text альтернатива.
- Кнопка отправки с градиентом, счётчики отправленных писем и файлов, подписи, типографика с трекингом.

### Возможности
- **Настройки** (`⚙` или тап по карточке статуса): почта, пароль приложения, имя отправителя, получатель по умолчанию, SMTP-хост, порт, переключатель SSL (465 / STARTTLS 587).
- **Сохранение настроек** в приватных `SharedPreferences` приложения (без `androidx.security`: приложение только для себя). Резервное копирование отключено в манифесте.
- **Проверка соединения** прямо из настроек (логин на SMTP без отправки письма).
- **Защита от скриншотов** на экране настроек (`FLAG_SECURE`), `allowBackup=false`, пароль никогда не пишется в логи.
- **Вложения через SAF** (`ACTION_OPEN_DOCUMENT`, в т.ч. несколько файлов): список с именем, размером, типом и удалением. Работает на Android 10+ без разрешения на хранилище — данные читаются потоком из `content://` Uri.
- **Черновик**: тема, текст и получатель сохраняются автоматически при выходе/повороте экрана.
- **Статистика** и валидация: проверка e-mail, сети, понятные сообщения об ошибках (логин / сеть / SMTP) с переходом в настройки.
- Очистка настроек с подтверждением, подсказка по получению пароля приложения со ссылкой на Google.

### Полировка кода (критические исправления)
| Проблема | Решение |
| --- | --- |
| Пароль приложения и почта в коде | Удалены, перенесены в настройки |
| Манифест ссылался на несуществующие `.SketchApplication` и `.DebugActivity` → краш при запуске | Объявления удалены |
| В `main` не было зависимостей Jakarta Mail (только `fileTree(libs)` с несохранёнными jar) | Добавлены `com.sun.mail:jakarta.mail:2.0.2` + `com.sun.activation:jakarta.activation:2.0.1` (можно переключиться на свои jar) |
| Вложения через `content:// → путь к файлу` не работают на Android 10+ (scoped storage) | Потоковый `DataSource` через `ContentResolver` |
| Запрос `READ_EXTERNAL_STORAGE` и `uses-library org.apache.http.legacy` | Удалены за ненадобностью |
| 4 попытки SMTP-конфигураций подряд с отдельными пулами потоков (до 40 с ожидания, утечка потоков) | Одно соединение с таймаутами, общий daemon-пул, явный `close()` |
| `Toast.getView()` на API 30+ возвращает `null` → NPE в `SketchwareUtil.CustomToast` | Мёртвый Sketchware-код удалён, используются `Snackbar` |
| `selectedFiles.get(0)` без проверки → краш при отмене выбора файла | Безопасная обработка результатов `Activity Result API` |
| HTML-инъекция: тема и текст подставлялись в письмо без экранирования | `escapeHtml()` для всех пользовательских данных |
| Лишние `google-services`, `jetifier`, `useLibrary`, отсутствие Gradle Wrapper и `.gitignore` | Конфигурация приведена к современному виду, добавлен Wrapper 8.13 |

## Сборка

Требования: **JDK 17**, Android Studio (Ladybug+) или Gradle 8.13, Android SDK 34.

```bash
./gradlew assembleDebug        # Windows: gradlew.bat assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
```

Либо откройте папку проекта в Android Studio и нажмите **Run ▶**.
Wrapper уже в репозитории — отдельно скачивать Gradle не нужно.

- `minSdk 21` (Android 5.0), `targetSdk 34`, AGP 8.12.0, Java 8.
- Зависимости: AppCompat, Material Components, AndroidX Activity, **Jakarta Mail 2.0.2 + Jakarta Activation 2.0.1**.
- В `app/build.gradle` есть переключатель `useOriginalJars`: если поставить `true`, библиотеки берутся из `app/libs/*.jar` — ровно как в исходном проекте (тогда Maven-зависимости не подключаются).

## Первый запуск

1. Откройте **Настройки** (иконка шестерёнки).
2. Укажите свою почту Gmail и **пароль приложения** (не пароль аккаунта).
   Пароль приложения: Google Аккаунт → Безопасность → двухэтапная аутентификация → Пароли приложений.
3. При желании задайте имя отправителя, получателя по умолчанию, хост/порт.
4. **Сохранить** → **Проверить соединение**.
5. Вернитесь, заполните письмо, добавьте файлы, нажмите **Отправить письмо**.

Если параметры не заданы, приложение само предложит открыть настройки.

> После обновления с 2.0 на 2.1 **один раз введите почту и пароль заново**: хранилище
> настроек изменилось (раньше было шифрованным, теперь обычное приватное).

## Версия 2.1 — исправление подключения

По логам падение было `MailConnectException`: соединение со SMTP не устанавливалось.
Причины и что сделано:

1. **Вернулись оригинальные библиотеки** — `com.sun.mail:jakarta.mail:2.0.2` и
   `com.sun.activation:jakarta.activation:2.0.1`, код снова на `jakarta.mail.*` / `jakarta.activation.*`.
   В версии 2.0 я ошибочно поставил `android-mail:1.6.7` (`javax.mail`) — это был лишний шаг.
2. **Вернул автоперебор SMTP-конфигураций**, который был в исходнике: сначала настройки
   пользователя, затем `smtp.gmail.com:587` (STARTTLS), `smtp.gmail.com:465` (SSL),
   `smtp.googlemail.com:587` и `:465`. Если провайдер блокирует порт 587, письмо уйдёт через 465.
3. **Вернул `android:usesCleartextTraffic="true"`** в манифест (нужно для STARTTLS).
4. Убрал `androidx.security:security-crypto:1.1.0-alpha06` — он не нужен для личного приложения.
5. Проверка сети теперь смотрит на `NET_CAPABILITY_INTERNET`, а не на тип транспорта.
6. При ошибке показывается диалог с **техническими деталями** (какие хосты/порты перебраны
   и текст исключения) — больше не надо гадать по логам.

## Структура

```
app/src/main/java/com/gmail/
├── MainActivity.java       экран письма, вложения, отправка, анимации успеха
├── SettingsActivity.java   настройки аккаунта и SMTP, проверка соединения

├── UriDataSource.java      потоковое чтение вложения без файловых путей

└── ConfettiView.java       конфетти на экране успеха
app/src/main/res/           layout / drawable (векторные иконки, градиенты) / values / mipmap
design-preview/             интерактивный HTML-макет трёх экранов + дизайн-система
```
